Case Study
Full-StackMulti-Tenant SaaSBuilt With Agents
Nov 2026

A team platform built on a shared record of finished work, specified and shipped in a day.

Wake turns short "done" entries into team feeds, a weekly digest, dashboards and reports. The 34-feature proposal was built phase by phase with the agentic engineering harness: a spec with failing proofs, test-first implementation, and a fresh verifier for each phase.

Most teams lose track of what they actually finished. The work happened. It is scattered across pull requests, tickets, chat threads and someone's memory of a Tuesday standup. When the weekly update or the quarterly review comes around, people reconstruct it from fragments.

Wake starts from a simple premise: if finishing something takes ten seconds to log, the log becomes the source everything else reads from. Members post one-line "done" entries with tags, links and an optional goal or project. Feeds, digests, dashboards, reports and planning tools are all views over that record.

The proposal was 34 features in five phases.

The product proposal laid out six modules: work log, planning, people and team health, insights, integrations, and platform and admin. Their 34 features were split into five release phases: core, visibility, planning, team health and enterprise. Phase 1 alone needed magic-link sign-in, organizations and teams, roles, entries, feeds, profiles, a scheduled weekly digest and per-seat billing.

That is not a weekend demo. It is the scope that usually gets a quarter of planning and a small team. The interesting question was whether a disciplined agent workflow could carry it without the codebase dissolving into untested features.

Each phase started as a spec with failing proofs.

The repository was set up with the agentic engineering harness first. Every phase then went through the same loop. A spec in .scratch/ stated the problem and the solution, and listed each "Done when" item with a pytest command marked fails today. "Must not change" proofs protected what earlier phases had built. Implementation went red-first, and a fresh harness-verifier ran every proof and reviewed the diff for spec gaps and standards issues before the phase was marked done.

Fourteen specs carried the build: three early slices (teams and entries, weekly digest, seat billing), then Phase 1 and the sub-phases 2a–2c, 3a–3c, 4a–4c and 5a–5b. Phases 1 through 5 were specified, built and verified between late morning and the 16:42 baseline commit on 11 November 2026. Each spec's log records the verdict, the local proof results, and anything deliberately left unbuilt.

The tenant boundary moved first.

The earliest version made the team the tenant. The Wake proposal needed organization-wide billing, feeds and roles, so the first architectural decision recorded was that the organization is the tenant, with teams exactly one level deep. It was changed before anything else was built, because every later feature would otherwise have been written against the wrong boundary. An isolation test suite fails if any route that takes an organization or team id can be reached from outside it.

Two more decisions became ADRs because they are hard to reverse. Pulse survey answers are stored with no person attached, so anonymity holds even against a database query, and results show only for weeks with at least three answers. Account deletion anonymizes what a person wrote instead of deleting it, so team feeds, retros and reports don't develop holes nobody chose.

Integrations were built against fakes, on purpose.

Slack commands, GitHub pull-request drafts and Linear issue drafts all use signed requests that the test suite can produce, with no live account. A merged pull request or a completed Linear issue becomes a draft entry for its author, which they confirm rather than auto-post. Each proof is labeled Local or Live in the spec logs, and the live ones are honestly marked as not run.

What exists, and what doesn't.

By the end of Phase 5 the suite stood at 748 passing pytest tests plus Playwright browser smoke tests. The app is a single FastAPI module with SQL through psycopg and numbered migrations, a React single-page front end built by Vite, and a Docker Compose stack for local runs. A follow-up pass built the sidebar workbench layout shown above.

Some things were deliberately not built. SSO, two-factor sign-in and the guest role were deferred. The digest command is safe to re-run, but nothing schedules it yet. There is no deployed environment, so every result here is local. Wake is a demonstration of how far a well-specified, verified agent loop can carry a real product scope. It is not yet a hosted service.
